Подготовка рабочего окружения

Научимся создавать, сохранять и проверять HTML-файлы, работать с папками и инструментами браузера.

Как заниматься: прочитай теорию, воспроизведи пример в отдельной папке, выполни задания без подсказок. Ответы раскрывай после попытки.

1. Редактор, браузер и файлы

Для первых шагов нужны текстовый редактор (например, VS Code) и современный браузер. Редактор изменяет исходный код, браузер интерпретирует его и показывает результат. Текстовый процессор вроде Word для HTML не подходит: он добавляет собственное форматирование.

2. Установка и настройка редактора

Установи редактор из официального источника. Открой в нём целую папку проекта через File → Open Folder. Установи удобный размер шрифта, включи автоматическое форматирование при желании. Расширения полезны, но необязательны; на первых уроках лучше понимать, что происходит без автоматизации.

3. Правильная структура проекта

Папка проекта содержит файлы страниц и отдельные каталоги для изображений, стилей и скриптов. Имена файлов удобно записывать латиницей, строчными буквами, через дефис. Это соглашение, а не требование HTML.

4. Расширения и кодировка

Файл должен называться index.html, а не index.html.txt. При сохранении используй UTF-8. В Windows включи показ расширений файлов, чтобы не спутать их. Двойной щелчок открывает локальную страницу по адресу file:///. Для простых HTML-примеров сервер не требуется.

5. Работа с DevTools

Открой страницу в браузере и нажми F12 (или Ctrl+Shift+I). На вкладке Elements/Inspector увидишь DOM, на Console — сообщения и ошибки JavaScript, на Network — запросы ресурсов. Названия и сочетания клавиш зависят от браузера и системы.

6. Когда нужен локальный сервер

Обычные HTML-файлы можно открывать с диска, но некоторые веб-API, модули JavaScript и загрузка данных через fetch работают иначе или ограничены при file://. Позже мы запустим локальный HTTP-сервер. Расширение Live Server — лишь один из вариантов, а не обязательная часть HTML.

7. Разбор примера

Перепечатай или скопируй пример в редактор. Если это структура папок, создай её вручную; если HTML — сохрани в файл с расширением .html. Проверь результат в браузере.

project/
├── index.html
├── pages/
│   └── heroes.html
├── images/
├── css/
│   └── style.css
└── js/
    └── script.js

Обрати внимание: пример предназначен для практики. Изменяй по одному элементу или атрибуту и наблюдай, как меняется результат.

8. Практические задания

Базовый уровень

Создай папку web-practice и внутри неё файл index.html. Вставь минимальный HTML-документ, сохрани и открой в браузере.

Средний уровень

Создай папки pages, images, css, js. В pages создай heroes.html с заголовком «Герои». Проверь обе страницы.

Сложный уровень

Открой DevTools, найди в DOM заголовок h1, временно измени его текст прямо в инструментах разработчика, обнови страницу и объясни, почему изменение исчезло.

Подсказки к практике

Сначала проверь: файл действительно сохранён, расширение верное, браузер обновлён, а путь к файлу совпадает с его расположением. Сравни свою структуру с примером выше. Для сложного задания объедини несколько приёмов из урока.

9. Самопроверка

  1. Чем отличается редактор кода от браузера?
  2. Почему важно проверять расширение файла?
  3. Зачем использовать UTF-8?
  4. Что такое DevTools и чем DOM отличается от исходного файла?
  5. Почему не всегда достаточно открыть страницу через file://?
Показать ответы
  1. Редактор создаёт и изменяет код, браузер отображает результат.
  2. Файл с .txt может не интерпретироваться как HTML.
  3. Чтобы корректно хранить и показывать символы разных языков.
  4. Инструменты разработчика помогают исследовать страницу; DOM — дерево, созданное браузером из разметки.
  5. Некоторые возможности требуют HTTP-контекста или имеют ограничения безопасности.
