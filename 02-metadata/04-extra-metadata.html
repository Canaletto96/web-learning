Дополнительные метаданные

Open Graph, карточки соцсетей, canonical, theme-color и границы возможностей метаданных.

Как заниматься: изучи объяснения по порядку, создай отдельную папку для экспериментов, набери примеры самостоятельно, затем выполни задания. Подсказки и ответы раскрывай после попытки.

1. Зачем нужны дополнительные метаданные

Помимо title, description и viewport, страница может содержать сведения для поисковых систем, мессенджеров, социальных платформ и браузерного интерфейса. Эти данные помогают внешним сервисам понять страницу, но не гарантируют, как именно она будет показана. Сначала делай качественное содержимое и базовые метаданные, затем добавляй дополнительные.

2. Open Graph — предпросмотр ссылок

Протокол Open Graph использует атрибут property у meta. Распространённые свойства: og:title, og:description, og:type, og:url, og:image. Сервисы могут брать данные и из других источников. Изображение должно быть доступно тому сервису, который создаёт предпросмотр.

<meta property="og:type" content="website">
<meta property="og:title" content="Каталог героев">
<meta property="og:description" content="Описание персонажей и их экипировки.">
<meta property="og:url" content="https://example.com/">
<meta property="og:image" content="https://example.com/images/preview.jpg">

Если открывать страницу через file://, социальные платформы не смогут получить локальный файл или локальную картинку по пути с твоего компьютера. Предпросмотр можно полноценно тестировать после публикации по доступному HTTPS-адресу.

3. Карточки X / Twitter

Некоторые сервисы поддерживают дополнительные метаданные, например twitter:card. Для большой карточки с изображением часто используется значение summary_large_image. Поддержка и правила отображения могут меняться, поэтому проверяй актуальную документацию нужной платформы.

<meta name="twitter:card" content="summary_large_image">

Не нужно бездумно дублировать все поля: многие платформы используют Open Graph как запасной источник.

4. canonical — предпочтительный URL

Для указания предпочтительного адреса страницы используют <link rel="canonical" href="...">. Это полезно, когда одинаковый или почти одинаковый контент доступен по нескольким URL, например с параметрами сортировки. Поисковики рассматривают canonical как сигнал, а не абсолютный приказ. Обычно указывают полный HTTPS-адрес основной версии.

<link rel="canonical" href="https://example.com/heroes/ledin.html">

Canonical не перенаправляет посетителя и не скрывает страницу. Для офлайн-файлов с вымышленным доменом не нужно добавлять фиктивный canonical: вернёмся к нему при публикации.

5. theme-color и цвет интерфейса

Некоторые браузеры используют theme-color для оформления частей интерфейса. Эффект зависит от браузера и операционной системы; на некоторых платформах он не заметен. Можно указать цвет для светлой и тёмной схемы с атрибутом media.

<meta name="theme-color" content="#123654">
<meta name="theme-color" content="#101827" media="(prefers-color-scheme: dark)">

Это не заменяет CSS-оформление страницы.

6. Favicon, manifest и иконки

Иконку вкладки обычно подключают через link rel="icon". Для устанавливаемых веб-приложений используется manifest-файл, подключаемый как rel="manifest". Это отдельная более сложная тема: наличие manifest само по себе не превращает сайт в полноценное PWA.

<link rel="icon" href="/favicon.svg" type="image/svg+xml">
<link rel="manifest" href="/site.webmanifest">

Для нашего локального учебника путь href="/favicon.svg" неудачен: при открытии через file:// ведущий слэш указывает на корень файловой системы. Используй относительный путь, например href="favicon.svg".

7. Язык, hreflang и структурированные данные

Основной язык документа указывают атрибутом lang у html, а не специальным meta. Для альтернативных языковых версий могут применяться ссылки rel="alternate" hreflang="...". Структурированные данные Schema.org часто встраивают в формате JSON-LD через script; это отдельная тема SEO, которую подробно разберём позже.

<html lang="ru">
<!-- На опубликованном сайте с реальными переводами: -->
<link rel="alternate" hreflang="en" href="https://example.com/en/">

Не указывай несуществующие языковые версии и не путай hreflang с автоматическим переводом.

8. Что важно для офлайн-сайта

  • Обычные title, charset, viewport и description работают в локальном HTML.
  • Open Graph можно записать локально, но внешний сервис не увидит страницу, пока она не опубликована.
  • Canonical и og:url должны указывать на реальные опубликованные адреса, а не выдуманные домены.
  • Проверяй значения в исходном коде и DevTools, а внешний предпросмотр — после публикации.
  • Не используй метаданные как замену семантическому HTML и хорошему содержимому.

9. Практические примеры

Метаданные будущей главной страницы

Адреса example.com ниже — учебные заглушки, перед публикацией их нужно заменить.

<!doctype html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Каталог героев</title>
  <meta name="description" content="Герои, умения и экипировка.">
  <meta property="og:type" content="website">
  <meta property="og:title" content="Каталог героев">
  <meta name="twitter:card" content="summary_large_image">
  <meta name="theme-color" content="#123654">
</head>
<body>
  <h1>Каталог героев</h1>
</body>
</html>

Подготовка к публикации

Этот фрагмент добавляют только когда известен реальный URL сайта.

<link rel="canonical" href="https://example.com/heroes/">
<meta property="og:url" content="https://example.com/heroes/">
<meta property="og:image" content="https://example.com/preview.jpg">

10. Практические задания

Базовый уровень

Добавь к локальной странице og:title, og:description и theme-color. Посмотри метатеги через DevTools.

Средний уровень

Составь метаданные для двух разных карточек героев; придумай осмысленные заголовки, описания и названия картинок для предпросмотра.

Повышенная сложность

Спроектируй метаданные для опубликованного каталога с русской и английской версиями. Отдельно укажи, какие URL станут действительными только после публикации, и почему нельзя проверить Open Graph предпросмотр через file://.

Подсказки к заданиям
  • Open Graph помогает сервисам формировать предпросмотр ссылок.
  • canonical обозначает предпочтительный URL, но не делает редирект.
  • theme-color влияет на поддерживаемые части интерфейса браузера.

  2. Может ли мессенджер прочитать файл с твоего диска через file://?
  3. Перенаправляет ли canonical пользователя?
  4. Что делает theme-color?
  5. Достаточно ли manifest для полноценного PWA?
  6. Где указывают основной язык документа?
Показать ответы
  1. Через property, например property="og:title".
  2. Нет, внешний сервис не имеет доступа к локальному файлу.
  3. Нет, это сигнал поисковикам.
  4. Может влиять на цвет частей интерфейса браузера.
  5. Нет.
  6. В атрибуте lang у элемента html.

12. Краткий конспект

  • Open Graph помогает сервисам формировать предпросмотр ссылок.
  • canonical обозначает предпочтительный URL, но не делает редирект.
  • theme-color влияет на поддерживаемые части интерфейса браузера.
  • Для проверки внешних метаданных обычно нужен опубликованный сайт.
