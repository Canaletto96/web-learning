Элемент title и метаданные

Кодировка, масштабирование на мобильных устройствах, описание и инструкции для поисковых роботов.

Как заниматься: изучи объяснения по порядку, создай отдельную папку для экспериментов, набери примеры самостоятельно, затем выполни задания. Подсказки и ответы раскрывай после попытки.

1. title — имя документа

Элемент <title> задаёт название страницы. Браузер обычно использует его для вкладки, закладок и истории. Поисковая система может использовать title как один из источников заголовка результата, но не обязана отображать его дословно. В документе должен быть один непустой, содержательный title; желательно уникальный для каждой страницы.

<title>Ледин — характеристики героя | Каталог</title>

2. meta charset — кодировка

UTF-8 поддерживает кириллицу и множество других символов. Сохраняй файл в UTF-8 и объявляй кодировку: <meta charset="utf-8">. Если файл сохранён в другой кодировке, одного meta недостаточно: текст может отображаться неверно. Декларация должна полностью находиться в первых 1024 байтах файла.

3. meta viewport — область просмотра

На мобильных устройствах браузер использует viewport для расчёта размеров страницы. Типичная запись width=device-width, initial-scale=1 позволяет CSS адаптироваться к реальной ширине экрана. Она не делает сайт автоматически адаптивным: нужны соответствующие стили. Не рекомендуется запрещать масштабирование через user-scalable=no или жёсткий maximum-scale=1 — это мешает доступности.

<meta name="viewport" content="width=device-width, initial-scale=1">

4. meta description — краткое описание

Описание часто используется поисковиками как возможный текст сниппета, но не гарантирует его отображение. Пиши естественно и по существу, с учётом конкретной страницы. Это не видимый абзац и не прямой фактор гарантированного повышения позиций.

<meta name="description" content="Характеристики, умения и снаряжение героя Ледин в игровом каталоге.">

5. meta robots — инструкции для роботов

Значения index и follow обычно являются поведением по умолчанию для индексирующих роботов, поэтому их явное указание часто не нужно. noindex просит поддерживающего робота не включать страницу в индекс, nofollow — не переходить по ссылкам или не учитывать их в соответствии с политикой конкретного робота. Директивы не являются механизмом безопасности: страница всё равно может быть доступна посетителям.

ЗаписьСмыслВажно
indexРазрешает индексированиеЧасто значение по умолчанию
noindexПросит не индексироватьРобот должен иметь доступ, чтобы прочитать директиву
followРазрешает следование ссылкамЧасто значение по умолчанию
nofollowПросит не следовать ссылкамТрактовка зависит от поисковика
noarchiveОграничение кешированной копииПоддержка зависит от робота
<meta name="robots" content="noindex, nofollow">

6. Атрибуты meta: name, content, http-equiv

Пара name + content задаёт именованные метаданные. http-equiv поддерживает ограниченный набор специальных директив (например, refresh), но не заменяет произвольные HTTP-заголовки сервера. charset — отдельная форма объявления кодировки. Нельзя считать, что любая строка в http-equiv станет HTTP-заголовком.

Автоматическое перенаправление через http-equiv="refresh" может ухудшать удобство и доступность; для постоянных перенаправлений предпочтительны серверные HTTP-редиректы.

7. Типичные ошибки

  • Одинаковый title на всех страницах каталога.
  • Description, состоящий из повторения ключевых слов.
  • Ожидание, что meta robots скроет страницу от посторонних.
  • Отключение масштабирования на телефоне.
  • Указание charset без сохранения файла в UTF-8.

8. Практические примеры

Страница героя

Скопируй код в файл hero.html и сравни вкладку с видимым заголовком.

<!doctype html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Ледин — карточка героя</title>
  <meta name="description" content="Карточка героя Ледин: роль, способности и экипировка.">
</head>
<body>
  <h1>Ледин</h1>
  <p>Описание героя будет здесь.</p>
</body>
</html>

Страница, которую не нужно индексировать

Используй только на тестовой странице и помни, что это не защита доступа.

<meta name="robots" content="noindex">

9. Практические задания

Базовый уровень

Сделай документ с уникальными title и description и корректным viewport.

Средний уровень

Создай две карточки героев; у каждой должны быть свои title и description, а заголовки h1 должны соответствовать содержимому.

Повышенная сложность

Сделай экспериментальную страницу с noindex, письменно объясни, почему она остаётся доступной по прямой ссылке, и перечисли два способа реально ограничить доступ на сервере.

Подсказки к заданиям
  • title — краткое, уникальное и понятное имя страницы.
  • description — возможный источник сниппета, не гарантия.
  • viewport помогает адаптивной вёрстке, но не заменяет CSS.

10. Самопроверка

  1. Где обычно отображается title?
  2. Гарантирует ли description текст сниппета?
  3. Зачем viewport?
  4. Какое поведение обычно подразумевается без index и follow?
  5. Почему noindex не защищает секретную страницу?
  6. Может ли meta http-equiv заменить любой HTTP-заголовок?
Показать ответы
  1. Во вкладке, закладках и истории браузера; поисковики тоже могут учитывать его.
  2. Нет.
  3. Чтобы корректно рассчитывать область просмотра, особенно на мобильных устройствах.
  4. Индексирование и следование ссылкам обычно разрешены, если нет иных ограничений.
  5. Он управляет поведением поддерживающих роботов, а не доступом пользователя.
  6. Нет, поддерживается ограниченный набор директив.

11. Краткий конспект

  • title — краткое, уникальное и понятное имя страницы.
  • description — возможный источник сниппета, не гарантия.
  • viewport помогает адаптивной вёрстке, но не заменяет CSS.
  • robots — инструкция роботам, а не защита доступа.
